# T7 summary — cosmology/size audit, group-mass covariate, code health

Hand-recomputation confirms the inherited convention: `size_Group_Bary_kpc` (and hence t_cr) in every `*_Groups` table converts angular size with the *luminosity* distance (the CSV value reproduces the D_L computation to machine precision), overestimating proper sizes by (1+z)² = 3.3–9.6% (median 7.2%), while M_virial uses the angular-diameter distance — an internal inconsistency inherited from the published Paper I pipeline, whose ⟨R_ij⟩ = 313 kpc reproduces only under D_L. Because no fitted model uses size or t_cr as a covariate (verified), we document rather than regenerate: a Sect. 2.1 footnote quantifies the bias, together with the second inherited convention that the exported `dist2BGG` column is radians×3600 (orderings unaffected; every consumer in this paper divides by 3600 and converts with D_A, as verified for the tidal R_ij, host-centric distances, radial diagnostics, and Simard/Petrosian sizes; the normalized radius R_norm inherits the smooth (1+z)² scale factor, diagnostics only). On group mass, the tables' `lMass_200` turns out to be the Yang–Lim abundance-matching M_180m of the *host* halo converted to M_200c (r = 0.99999 with host logM_180; r = 0.19 with the quartet virial mass), so Appendix F.4 now explains its exclusion (host-halo semantics that differ across samples, near-collinearity with the group-luminosity covariate, selection entanglement) and reports the requested sensitivity fit: adding log M_200c leaves every elliptical conclusion unchanged (pooled OR 1.77 → 1.62; per-control 2.00/1.56/2.65, all p < 0.005). The `np.clip(-1, 1, x)` argument-order defect was found at three sites in the circumcircle helper (and one benign site in legacy `common.py`), shown to affect no shipped quantity (its only caller is the legacy 'Circ' branch the pipeline never executes), and fixed.
